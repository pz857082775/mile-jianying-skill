# 功能完善规划

> 目标：让用户用自然语言描述需求即可完成剪辑，并能对成片的特定片段下达精准优化指令；每次剪辑留下结构化记忆，同类视频越剪越顺手。
> 基线：`mile-jianying-skill` v1.0.0（2026-10-29）
> 原则：核心链路本地、确定性、可回滚；语义/云端能力可插拔；不破坏剪映未知字段。

---

## 1. 目标拆解

用户的目标可以拆成两条主线 + 一个闭环：

```text
主线 A：从需求到成片
自然语言 → 意图理解 → 剪辑计划 → 组装/生成 → 质检 → 交付

主线 B：对成片精准优化
自然语言 + 时间/画面/文字线索 → 片段定位 → 局部修改 → 差异预览 → 质检 → 交付

闭环 C：记忆
每次 A/B 的意图、计划、结果、反馈 → 结构化记忆 → 下次召回风格与经验
```

1.0.0 已经完成：

- 主线 B 的执行层（timeline / find / edit / plan / qa）
- 主线 A 的底稿层（assemble / JyProject）
- 闭环 C 的基础版（记录 / 召回 / 反馈 / 遗忘）
- 主线 A/B 的翻译层第一版（`smart`：中文意图 → 计划，规则版，零重型依赖）
- 字幕整理（错写纠正 + 术语保护 + 断句/排版）与 BGM、转场推荐（`subtitles` / `recommend`）
- 媒体智能的第一块：可选 ASR 接入位（未安装 faster-whisper 时明确返回 `ASR_UNAVAILABLE`，不伪造能力）

尚未完成：

- 意图层的 LLM 后端与歧义候选追问（当前是规则/槽位解析 + `clarify` 文案）
- 主线 B 的差异预览 `preview.py`（当前用 `plan` 校验 + `smart` 默认 dry-run 承担）
- 闭环 C 的「语义向量召回 + 偏好学习 + 系列风格档案」
- 媒体智能的高阶部分：高光检测、卡点剪辑、自动构图、批量变体、真实音频特征级推荐

### 2.2 设计约束

1. **不引入必装大依赖**：ASR、Embedding、LLM 全部 optional；缺失时退化为现有词法/规则能力。
2. **所有修改可预览**：自然语言指令必须先转成计划，展示「将修改哪些片段、怎么改」，再执行。
3. **低置信度不猜**：返回候选与追问，而不是静默改错。
4. **记忆可解释**：每次召回要说明「因为哪些特征相似」，而不是黑盒推荐。
5. **剪映兼容优先**：只改已知字段，未知字段原样保留；剪映升级后可快速适配。

**目标**：把「一句话剪片 / 一句话改片」真正打通，同时保持零重型依赖可运行、不伪造媒体理解能力。

- **依赖与文档**：`pyproject.toml` 增加可选 `audio-analysis`（numpy）与 `asr`（faster-whisper）extra；README / SKILL / `rules/smart-edit.md` / `rules/cli.md` / `docs/api.md` 同步智能层用法与能力边界。

### 阶段 P1：自然语言入口与记忆增强（部分完成，其余建议 2–3 周）

**主题：自然语言入口 + 记忆增强**

#### P1-1 意图层 `scripts/mile/intent.py`（规则版已完成 1.0.0 · LLM 后端待做）

职责：

- 输入：自然语言 + 可选草稿上下文（timeline 摘要、字幕、记忆）。
- 输出：

```json
{
  "intent": "把第 28 秒那个转场去掉",
  "confidence": 0.92,
  "plan": {
    "ops": [
      {"op": "remove_transition", "target": {"at": "28s", "role": "main"}}
    ]
  },
  "explain": "定位到主轨 27.5s-31.2s 片段，移除其与后一片段之间的叠化转场",
  "questions": []
}
```

- 规则优先：时间码、片段序号、文字包含、角色词（字幕/BGM/转场）用正则和词典解析。**（1.0.0 已实现，含转场添加/移除、音轨路径抽取、无路径音乐诉求降级为推荐）**

- 低置信度：返回 `questions`，例如「你说的‘那个转场’是 27.5s 的叠化，还是 31s 的闪白？」**（1.0.0 以 `clarify` 文案实现，尚无候选片段选择）**
- 安全：intent 只生成计划，不直接改草稿。**（已实现：`smart` 默认 dry-run，`clarify` 非空时不落盘）**

#### P1-5 批量变体 MVP `scripts/mile/variants.py`（新增）

#### P2-4 音频与节奏

- BGM 卡点：节拍检测 + 切点对齐。
- Ducking：人声出现时自动压低 BGM。
- 响度归一化：目标 LUFS，避免平台压缩后忽大忽小。
- 转场时长随节拍自适应。

#### P2-5 质量检查升级

新增媒体级检查（需 ffmpeg，可选）：

- 黑帧 / 静止帧 / 花屏；
- 静音段 / 爆音 / 响度超标；
- 音画不同步（基于语音活动与字幕）；
- 字幕溢出画面 / 遮挡主体；
- 导出参数与平台规范不符。

每条问题给出「证据（时间点/片段）+ 建议修复」，并支持 `qa --fix` 的安全子集。

#### P2 验收标准

- 10 条口播素材，自动字幕与人工校对差异 < 5%。

- BGM 卡点误差 < 100ms。

### 阶段 P3：Agent 闭环与生态（建议 8–12 周）

**主题：Agent 闭环 + 生态**

#### P3-1 规划-执行-验证闭环

- Agent 循环：理解 → 计划 → 预览 → 执行 → 质检 → 自修复 → 汇报。
- 自修复策略库：缺素材、时长越界、轨道重叠、字幕为空等常见错误的自动处理。
- 失败时给出「最小回退方案」，而不是整单失败。

#### P3-2 记忆驱动的个性化导演

- 从历史记忆学习：
  - 开场 3 秒偏好；
  - 镜头平均时长与切点密度；
  - 转场偏好；
  - 字幕样式与位置；
  - BGM 风格与音量。
- 新项目自动生成「导演建议」，用户一键采纳或修改。
- 支持「反常规」标记：某条视频刻意打破历史风格时，不污染系列档案。

#### P3-3 协作与交付

- 计划文件与记忆包可分享，支持团队审阅。
- 差异 diff（谁改了什么）与评论锚点（时间码 + 片段 ref）。
- 导出前检查清单与平台规范模板。

#### P3-4 插件与 MCP

- 将 `mile_cli.py` 暴露为 MCP Server：
  - tools: `timeline`、`find`、`edit`、`plan`、`qa`、`memory_recall`、`assemble`；
  - resources: 草稿列表、时间轴、记忆档案。
- 允许第三方扩展 op（例如自定义字幕样式、品牌模板）。
- 插件市场/模板市场（长期）。

#### P3 验收标准

- 复杂需求（5 步以上）一次完成率 ≥ 70%，人工干预 ≤ 1 次。
- 自修复覆盖率 ≥ 60% 的常见结构问题。
- MCP 工具在 Qoder/Claude 等客户端可用。

## 4. 「精准优化指令」专项设计

这是用户目标中最关键、也最容易做砸的部分。建议按以下流程实现：

### 4.1 指令解析

| 用户说法 | 解析结果 |
|---|---|
| 把第 28 秒那个转场去掉 | `remove_transition` + `at=28s` + `role=main` |
| 第二句字幕改短一点 | `set_text` + `role=caption` + `text_contains=第二句` + 改写策略 |
| 开头太拖，前 3 秒剪掉 | `trim` + `range=0s-3s` + `ripple=true` |
| BGM 太吵 | `set_volume` + `role=bgm` + `volume=当前值×0.7` |
| 把这个片段放大到全屏 | `set_transform` + `ref=...` + `scale=1.0` |
| 给所有字幕加描边 | `set_text` 批量 + `role=caption` + `border=...` |

### 4.2 定位与置信度

- 先走确定性选择器：时间、ref、文字、角色、轨道。
- 多候选时返回候选列表 + 每个候选的上下文（时间、文字、缩略图）。
- 置信度低于阈值（建议 0.75）时**不执行**，改为追问。
- 所有定位结果必须带 `ref`，确保可复现。

### 4.3 修改前预览

预览内容：

- 目标片段：时间、轨道、文字、素材名；
- 修改前/后属性；
- 影响：总时长、后续片段位移、轨道变化；
- 风险提示：例如「裁剪后该片段仅剩 0.2 秒」「删除后主轨出现 1.5 秒空隙」。

### 4.4 执行与回滚

- 默认备份；
- 执行后自动 `qa`；
- 失败自动回滚；
- 提供 `undo` 与 `backups`；
- 记忆记录「用户是否接受」。

### 4.5 多轮对话

- 支持「再短一点」「刚才那个不要了」「回到上一版」。
- 维护会话级编辑栈：不依赖用户重复描述。
- 会话结束自动总结为一条记忆。

## 5. 记忆增强专项设计

### 5.1 记忆分层

```text
L1 会话记忆：本次对话的操作栈与临时偏好（进程内/短期文件）
L2 项目记忆：单个草稿/项目的编辑历史与风格
L3 系列记忆：同一账号/栏目的风格档案（跨项目）
L4 全局偏好：用户长期偏好（字体、颜色、节奏、平台）
```

当前 1.0.0 只有 L2 + 部分 L4。建议按层补齐。

### 5.2 记录内容（扩展版）

```json
{
  "id": "m-...",
  "scope": "series:科技评论",
  "intent_raw": "把开场收紧，字幕换成品牌黄",
  "intent_plan": {"ops": [...]},
  "targets": [{"ref": "...", "role": "main", "start": 0, "end": 2.5}],
  "outcome": "accepted",
  "feedback": {"rating": 5, "notes": "节奏合适"},
  "style": {"font_size": 9, "color": "#FFD400", "transition": "叠化", "avg_shot_ms": 1800},
  "structure": {"tracks": 4, "cuts": 18, "duration": 42.5},
  "transcript": {"summary": "...", "keywords": ["..."]},
  "created_at": "2026-10-29T...",
  "app_version": "1.0.0"
}
```

### 5.3 召回策略

1. 过滤：项目/系列/平台/时长范围。
2. 粗排：词法 + 结构 + 风格（现有）。
3. 精排：可选向量相似度 + 反馈评分 + 时效。
4. 解释：输出「为什么召回这条」。
5. 应用：只提供建议，默认不自动覆盖用户显式参数。

### 5.4 隐私与治理

- 默认本地存储；
- 支持按项目/时间清理；
- 支持导出/导入（换机迁移）；
- 敏感字段（原文、字幕）可配置不落盘，只存摘要；
- 明确告知用户记忆用途。

## 11. 结语

1.0.0 已经把「可靠地改草稿」这件事做扎实了，并且第一版补上了「一句话指令」的翻译层与字幕/推荐的媒体入口。接下来的重点不是继续堆功能，而是把剩下的拼图补齐：

1. **让翻译层更懂人话**（intent 的 LLM 后端、歧义候选追问、真实语料基准）；
2. **把记忆从日志变成可复用的风格资产**（profile + semantic + 负反馈）；
3. **把媒体理解做深**（词级 ASR 对齐、高光、卡点、构图、内容级 BGM/转场推荐）。

这三块完成后，「一句话剪片 + 一句话改片 + 越剪越懂你」才真正从规则可用升级为理解可靠。
